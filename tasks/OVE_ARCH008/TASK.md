# OVE_ARCH008: Build the contract-first pipeline with an additive-only compatibility check

## 1. Summary

One definition per concept: zod schemas in `packages/contracts` generate TypeScript types, JSON Schema, an OpenAPI 3.1-style API document and the typed `api-client` surface. A compatibility check compares the generated schema with a committed snapshot and fails CI on any breaking change unless the API major version is explicitly bumped.

## 2. Context

Spec 13 (herdr pattern): public JSON API with a schema generated from types, changes only additive, new fields always optional. The UI, Telegram adapter, future CLI, agents (via the "overmind" Skill, ADR 0027) and third parties depend on stable shapes, and many agents change contracts in parallel, so the check must be mechanical and conflict-free (one snapshot file per entity).

## 3. Scope (in)

- `defineRoute()` / `defineEvent()` / `defineEntity()` helpers (declarative metadata around zod schemas).
- Generator CLI `pnpm contracts:generate` producing: JSON Schema per entity/route/event, one OpenAPI-like document, TS types for `api-client` (client method signatures and DTO type re-exports).
- Snapshot format, `pnpm contracts:snapshot`, `pnpm contracts:check` with the additive-only diff rules and the version-bump rule.
- Documentation `docs/architecture/contracts-pipeline.md` (author guide with examples).

## 4. Out of scope

- Barrel/aggregator generation, route auto-registration, extension-point generators: `OVE_ARCH009`.
- Writing individual entity schemas: each area. Gateway transport and the actual client runtime (`createClient`, transports): ENGINE.
- Event envelope schema: `OVE_ARCH010` (it registers events using `defineEvent`).

## 5. Detailed requirements

1. **Source layout.** Contract files live under `packages/contracts/src/<entity>/` (one folder per entity, CONVENTIONS section 5). Each exports zod schemas and registers metadata through helpers; no side-effect registries at import time (the generator imports files and reads exported `contractMeta`).
   ```ts
   export const PauseState = defineEntity('PauseState', z.object({ paused: z.boolean(), since: isoDateTime.optional(), reason: z.string().max(200).optional() }));
   export const pauseGlobalRoute = defineRoute({
     id: 'pause.global.set', method: 'POST', path: '/v1/pause/global',
     request: z.object({ paused: z.boolean() }),     // body
     params?: z.object({...}), query?: z.object({...}),
     response: PauseState.schema,
     errors: ['perm.local_approval_required', 'gateway.unauthenticated'],   // codes from ARCH003 catalogue
     scope: 'owner' | 'agent' | 'channel:telegram'[], idempotency: 'none'|'key-required'|'natural',
     summary: 'Set Global Pause', tags: ['pause'], stability: 'stable'|'experimental',
   });
   ```
   Path pattern: `/v1/<resource>/<action>`; ids as path params; method semantics (GET safe, PUT/DELETE idempotent). `defineEvent('run.node.started', schema, { persisted: boolean })` is specified by ARCH010.
2. **Generated artefacts** (all under git-ignored `packages/contracts/generated/` except the snapshot):
   - `json-schema/<Entity>.schema.json`, `json-schema/routes/<id>.json`, `json-schema/events/<type>.json` using zod's native JSON Schema conversion (`z.toJSONSchema`, target draft 2020-12) with `io: 'input'` for requests and `'output'` for responses.
   - `openapi.json`: OpenAPI 3.1 document (`info.version` = `API_VERSION`, paths from routes, components from entities, standard error response `ErrorResponse` from ARCH003, security schemes `ownerToken`, `agentToken`).
   - `packages/api-client/src/generated/{types.ts,routes.ts}`: DTO types via `z.infer` re-exports, and a `routes` table `{ [routeId]: { method, path, request: ZodType, response: ZodType } }` that the client runtime uses to build typed methods `client.call(route, input)`. Generated files carry a header `// GENERATED by tools/contracts, do not edit` and are git-ignored; they are produced by `pnpm gen` before `typecheck`, `test`, `build` (package scripts `pre*` hooks, CI step).
   - `docs/api/openapi.json` is NOT committed (artifact in CI, optional publication later).
3. **Snapshot.** `packages/contracts/snapshots/current/` is committed and contains one normalised file per contract unit: `entities/<Entity>.json`, `routes/<id>.json`, `events/<type>.json`, `errors/<area>.json` (codes + http + retryable, from ARCH003), `config/<section>.json`. Normalisation: sorted keys, `$schema` removed, `description` removed from comparison, enum arrays sorted only when marked unordered. One file per unit keeps parallel PRs free of merge conflicts. `snapshots/VERSION.json` holds `{ "apiVersion": "1.0", "snapshotOf": "1.0" }`. `API_VERSION = { major, minor }` is exported from `packages/contracts/src/version.ts`.
4. **Compatibility rules** (`pnpm contracts:check`; each violation has a stable id):
   Allowed (additive): new entity/route/event/error code/config section; new **optional** property in a response, event or entity; new optional property in a request; new enum member in a response/event/entity schema marked `.meta({ openEnum: true })` (clients must tolerate unknown members; enums without the flag are closed); widening a numeric range (bigger `max`, smaller `min`); new optional query parameter; `description`/`title`/`examples` changes; marking something `deprecated`.
   Breaking (fails unless major bump): removing or renaming any property/route/event/error code/enum member; changing a type; making an optional property required; making a required request field of a new kind required in an existing request; narrowing ranges, patterns, lengths; changing path, method or `scope` to a narrower audience; changing `idempotency`; removing a declared error code from a route; changing `persisted` of an event; new enum member in a closed enum in a response; changing `additionalProperties`; changing a default value.
   Output lists each finding with unit, JSON pointer, rule id and a hint.
5. **Workflow.**
   - `pnpm contracts:check` regenerates in memory and compares with `snapshots/current`:
     1. identical: OK;
     2. only additive differences: FAIL with `CONTRACT_SNAPSHOT_STALE` and the message "run `pnpm contracts:snapshot` and commit the changed snapshot files" (so the snapshot always mirrors the code and reviewers see the contract diff in the PR);
     3. any breaking difference: FAIL with `CONTRACT_BREAKING_CHANGE`, unless `API_VERSION.major` is greater than `snapshots/VERSION.json.apiVersion` major, in which case the previous snapshot is archived as `snapshots/v<N>/` by `pnpm contracts:snapshot --major` and the check passes with a note. A minor bump is automatic for additive changes (`snapshot` command increments `minor`).
   - `pnpm contracts:snapshot` is the only writer; it refuses to write a breaking diff without `--major`.
   - Breaking changes also require an entry in `docs/api/CHANGELOG.md` (check verifies the file mentions the new major).
6. **Runtime tolerance** rules documented for clients: ignore unknown properties in responses and events; treat unknown enum members of open enums as `unknown`; never depend on property order. Requests from older clients must keep validating (new request fields optional).
7. **Validation at the edge:** the gateway validates every request/response in non-release builds and every request in release builds with the route's zod schemas (ENGINE implements; this task states the rule). Response validation failure in dev is a test failure, in release a logged `internal` error.
8. **Determinism:** generation is deterministic (stable ordering), runs in under 30 s for 500 units, and fails on duplicate route ids, duplicate `(method, path)` pairs, duplicate entity names, routes referencing unknown error codes, schemas using unsupported zod features (transforms, refinements on the wire, `z.function`, `z.date()` instead of ISO strings, `z.bigint`, `z.map/set`); allowed wire primitives are string/number/boolean/null/array/object/union/literal/enum/record.
9. **Fixtures proving the check** (in `tools/contracts/fixtures/`): a base contract set plus one mutated copy per rule (remove field, rename field, optional->required, add optional field, add enum value open/closed, narrow max, remove route, change method, change error list, change event persisted). The test table asserts the exact classification and rule id for each.
10. CI contract: `pnpm gen && pnpm contracts:check` is a required job (fragment in `tools/contracts/ci-job.yml` for SETUP006).

## 7. Reuse

## 8. Architecture and code placement

- Library helpers in `packages/contracts/src/api/define-route.ts` and `src/kernel/meta.ts` (pure, browser-safe).
- Generator and checker in `tools/contracts/{generate.ts,openapi.ts,normalize.ts,diff.ts,snapshot.ts,check.ts,cli.ts}` (Node-only dev tooling; may import contracts, never imported by packages).
- Dependency note: rely on zod's built-in JSON Schema output (zod 4). If the pinned zod version lacks it, `zod-to-json-schema` is the fallback with a written justification (SETUP008).

## 9. Security and safety

Contracts are the validation boundary against untrusted input (agents, Telegram, web content): every field that carries free text MUST have `.max()` bounds and strict objects (`.strict()` on requests) so unexpected fields are rejected, not ignored. The check enforces that request schemas are strict objects and strings are bounded (rule `CONTRACT_UNBOUNDED_STRING`, warning level for entities, error level for requests). `scope` metadata documents which caller classes may call a route (owner, agent, telegram); the gateway authorises from it, so narrowing/widening scope is classified (widening scope = breaking security review: rule `CONTRACT_SCOPE_WIDENED` requires the label `security-reviewed` in the snapshot commit message trailer, checked in CI via PR metadata, ASSUMPTION).

## 10. Errors and edge cases

- Two PRs add the same route id: second fails generation after rebase (clear message).
- A schema uses `z.lazy` recursion: JSON Schema `$ref` supported, depth cap 8 for normalisation.
- Snapshot file edited by hand: check recomputes and reports mismatch; hand edits are overwritten by `snapshot`.
- Stale generated code in `api-client`: `pnpm gen` is a prerequisite of typecheck, so it cannot compile against old types.
- Merge conflicts in snapshots: only when two PRs change the same unit; resolve by re-running `snapshot` after rebase.
- Experimental routes (`stability: 'experimental'`): excluded from the breaking rules but still listed; never allowed for agent-scope routes.

## 11. Acceptance criteria

- [ ] `pnpm contracts:generate` produces JSON Schema, OpenAPI 3.1 and api-client types deterministically (two runs byte-identical).
- [ ] Every mutation fixture is classified exactly as specified (additive vs breaking) with the right rule id.
- [ ] Breaking change fails `contracts:check`; the same change passes with a major bump plus archived `snapshots/v<N>/` and a CHANGELOG entry.
- [ ] Additive change fails with `CONTRACT_SNAPSHOT_STALE` until `contracts:snapshot` is run.
- [ ] Duplicate route ids, unknown error codes and unsupported zod types fail generation.
- [ ] Request schemas that are not strict or contain unbounded strings are reported.
- [ ] Snapshot is split per unit (no single large file) and normalised.
- [ ] `docs/architecture/contracts-pipeline.md` documents authoring, check and bump procedures with an example.

## 13. Parallelization notes

Start with `defineRoute/defineEntity/defineEvent` helpers (unblocks every contract author), then generator, then check. Areas add contract files and run `contracts:snapshot` in their own PR; snapshot per-unit files avoid conflicts. Hotspot: `snapshots/VERSION.json` (minor counter) is touched by every additive PR, so the minor number is NOT incremented per PR; instead `VERSION.json` is rewritten only by release tooling (SETUP014) and `snapshot` records changes without touching `minor`. (Decision to avoid a permanent merge hotspot.)

## 14. Open questions and assumptions

- ASSUMPTION: zod 4 native `toJSONSchema` is available at the pinned version; confirm in SETUP008.
- ASSUMPTION: "OpenAPI-like" means a valid OpenAPI 3.1 document for documentation and for third-party client generation; the project's own client does not use it at runtime.
- ASSUMPTION: API version starts at `1.0`; pre-1.0 internal churn before the first release is handled by simply regenerating the snapshot (`--major` not needed until `release/1.0`, controlled by `VERSION.json.frozen: false`).
