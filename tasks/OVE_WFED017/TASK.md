# OVE_WFED017: Add round-trip tests, golden fixtures and parity vectors for the three mappers

## 1. Summary

Proves that nothing is lost between persisted definition, editor document and canvas model, and that the editor agrees with the server on cycles and ports. Provides golden fixtures (the mock workflow "Dostarczanie funkcji", an empty workflow, a 200-node stress workflow, hostile files) used by every later test.

## 2. Context

The workflow editor is written in two parts. PART 1 (`OVE_WFED001`..`OVE_WFED049`, this task) is the editor core and the canvas behaviour. PART 2 (`OVE_WFED050`..`OVE_WFED099`, another author) is the page route and feature manifest, the workflow header, the Agent Inspector, the Chief supervision strip, the run overlay, validation display and the publish flow. PART 2 consumes the capabilities `lib:editor-document-model`, `lib:editor-commands`, `lib:workflow-mappers` and `lib:editor-session` from PART 1. The mappers are pure and carry the data integrity of the editor: a lost field would silently change a Workflow program (ADR 0002). The mock Workflow "Dostarczanie funkcji" (Main view) is the reference: Start, Product Owner and Designer in parallel, Join, discussion "Zakres MVP", then the Loop "Pętla jakości" with Developer (TOR BUILD), QA (TOR QA), Security, Quality Gate, Senior Reviewer (TOR REVIEW), a dashed return edge, and "zapisz Decyzje".

## 3. Scope (in)

- Fixture set (definitions as JSON files).
- Round-trip tests Definition -> Document -> Definition and Document -> Definition -> Document.
- Golden snapshot of the canvas projection.
- Parity vectors with the server rules (`cycle-vectors.json` of WFED004, port compatibility table).
- Hostile-input corpus for mappers and fragments.

## 4. Out of scope

- The mappers themselves (WFED013, WFED015, WFED016).
- Visual regression (WFED048), e2e (WFED047).

## 5. Detailed requirements

1. Fixtures (`testing/fixtures/*.definition.json`, deterministic, no timestamps): `mock-delivery` (the graph described above, 14 nodes, 15 edges, 1 loop group, 3 lanes, 2 Skills overrides), `empty-start-end`, `parallel-join`, `loop-return`, `stress-200` (200 nodes, 300 edges generated by a seeded script committed as a fixture builder), `future-schema` (`schemaVersion: 2`), `dangling-edge`, `duplicate-key`, `unknown-node-type`, `config-null`, `proto-pollution`. A `testing/mock-workflow.ts` exports typed accessors.
2. Round-trip tests: for every valid fixture `definitionFromDocument(documentFromDefinition(x).doc)` deep-equals `normalizeDefinition(x)`; for every builder-made document the reverse holds; property test with a seeded generator (200 random valid definitions with random optional fields) holds both directions.
3. Preservation test: nodes of unknown type and arbitrary extra `config` content survive a round trip untouched (`toStrictEqual`), including key order of `config` objects.
4. Golden canvas test: the projection of `mock-delivery` matches a committed snapshot (node kinds, tab words, skills counts, edge states, frame rect); an intentional change requires updating the snapshot and mentioning it in the PR.
5. Parity tests: the vectors of WFED004 (`cycle-vectors.json`) give the same verdict through `wouldCloseRawCycle` as the documented server algorithm; a table of 20 (source schema, target schema, expected) cases for `checkConnection` copied from the WFRT012 examples; a `TODO-linked` check: when WFRT tasks add their own vector files, this test imports them (soft: skipped if absent, never silently passing: it logs "parity vectors from WFRT not found").
6. Hostile corpus: each hostile fixture produces the documented error or repair code, never an exception; `parseFragment` and `documentFromDefinition` are fed the same corpus plus a 1 000-string fuzz.
7. All fixtures are validated against `assertDocumentInvariants` where they are expected valid.

## 9. Security and safety

Fixtures are synthetic: no real Agent names, paths or secrets; hostile fixtures contain only inert strings. The corpus guards the import boundary.

## 10. Errors and edge cases

- A fixture accidentally edited: golden test fails with a readable diff.
- The server adds a node type: unknown type fixture still passes (data preserved).

## 11. Acceptance criteria

- [ ] All fixtures load through their documented path; every round-trip property passes 200 seeded cases.
- [ ] The golden snapshot exists and is reviewed.
- [ ] The stress fixture has exactly 200 nodes and 300 edges and passes invariants.
- [ ] The hostile corpus yields no uncaught exception.
