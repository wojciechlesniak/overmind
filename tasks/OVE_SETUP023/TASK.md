# OVE_SETUP023: Generate `tasks/INDEX.md`, `tasks/DEPENDENCIES.md` and `blocks` from front matter

## 1. Summary

A generator that turns the front matter of all tasks into two committed, deterministic overview files and (optionally) writes the reverse `blocks:` list into each task. CI verifies the committed files are up to date. The files contain only static metadata, never live status, so task PRs do not conflict on them.

## 2. Context

CONVENTIONS section 1: `INDEX.md` and `DEPENDENCIES.md` are generated from front matter and never hand-edited. Many PRs run in parallel, each flipping its own task to `done` (OVE_SETUP013); if the index contained status, every PR would conflict. Therefore live state is shown by `pnpm task:status` and `pnpm task:next`, not by the committed files.

## 3. Scope (in)

- `tools/tasks/gen-index.ts` with flags `--check` (exit 1 if files differ), `--write-blocks` (write `blocks:` into each TASK.md front matter), default: write the two files.
- Initial generated `tasks/INDEX.md` and `tasks/DEPENDENCIES.md`.

## 4. Out of scope

- Live status dashboards: OVE_SETUP013 (`task:status`).
- Validation: OVE_SETUP022.
- Resolving `needs` into `depends_on` (the "linker pass" done once by the backlog maintainers): this task provides `--suggest-links` output only (see requirement 5).

## 5. Detailed requirements

1. **`tasks/INDEX.md`:** header with "Generated by `pnpm gen:task-index`. Do not edit." (no date). Summary counts per area (tasks, by priority, by size). One table per area in area-table order: `ID | Title | Kind | Size | Priority | MVP | Depends on | Provides`. IDs link to `OVE_X/TASK.md`. Rows sorted by ID. Cancelled tasks listed in a separate "Cancelled" table at the end.
2. **`tasks/DEPENDENCIES.md`:** (a) per task: `depends_on`, `soft_depends_on`, `blocks` (computed), (b) topological layers ("wave 0" are tasks without dependencies, wave N depends on at most wave N-1), (c) the critical path (longest dependency chain by task count, printed as arrows), (d) a Mermaid `flowchart LR` per area limited to dependencies inside the area plus nodes for cross-area dependencies drawn as ids only, (e) a list of capability providers and consumers table (`capability | provider | consumers`).
3. **`--write-blocks`:** inserts or updates `blocks: [ ... ]` (sorted) after `adr_refs` in each front matter, preserving other lines and comments (text-level edit, not a full YAML re-serialisation). Idempotent. Used only by maintainers during linker passes, never by task PRs; the linter (OVE_SETUP022) checks it is not stale.
4. **`--check`:** regenerates in memory and compares byte-for-byte; prints a unified diff on mismatch; CI job `architecture` (OVE_SETUP006) calls it when the file exists.
5. **`--suggest-links`:** prints for each unresolved or unlinked `needs` the proposed `depends_on` edit (`OVE_X needs ui:Button -> add OVE_DS004`), without writing anything.
6. **Determinism:** Unix line endings, sorted keys and lists, no timestamps, no absolute paths, stable Mermaid node IDs (the task ID); running twice yields identical output.
7. **Size:** the files stay reviewable; Mermaid diagrams are split per area; if a diagram exceeds 150 nodes, it is split into waves.
8. **Failure behaviour:** if the model has cycles or unknown dependency IDs, the generator exits 1 and writes nothing (fail closed) with the same diagnostics as the linter.

## 7. Reuse

## 8. Architecture and code placement

`tools/tasks/gen-index.ts` is a thin CLI over pure render functions `renderIndex(tasks): string`, `renderDependencies(tasks): string`, `applyBlocks(text, blocks): string` in the same folder (`tools/tasks/render/*.ts`, owned here).

## 9. Security and safety

- Input is repository text; output is Markdown. Task titles are escaped for Markdown tables (`|`, backticks, `<`) and in Mermaid labels, so a malicious title cannot inject HTML or break the diagram (labels use IDs only).
- `--write-blocks` edits files in place: it refuses to run with a dirty tree outside `tasks/`, writes atomically (temp file + rename) and never changes anything except the `blocks:` line.
- No network, no shell, no `eval`.

## 10. Errors and edge cases

- Task with no dependencies and no dependents: appears in wave 0 and has `blocks: []`.
- `blocks` line absent: inserted; present and wrong: rewritten.
- Front matter with Windows line endings: error from the linter; generator refuses.
- Title containing `|`: escaped as `\|`.
- Very large backlog: Mermaid truncated per rule 7, with an explicit note.

## 11. Acceptance criteria

- [x] `pnpm gen:task-index` twice in a row produces no diff the second time.
- [x] Changing a task title and not regenerating makes `pnpm gen:task-index --check` fail with a diff.
- [x] `--write-blocks` adds correct reverse edges; running again changes nothing.
- [x] Given a cycle, the generator exits 1 and leaves the files untouched.
- [x] INDEX contains no status or date; DEPENDENCIES contains critical path and capability table.
- [x] A title with `|` and backticks renders safely (test).
