# OVE_AGENT011: Define AgentMessage contract, domain rules and storage

## 1. Summary

An Agent Message is a direct message between Agents inside a Run (SPEC 14: `id, runId, sender, recipient, payloadRef, correlationId, timestamp`). This task defines the entity, the delivery rules (who may message whom), size limits and the SQLite table.

## 2. Context

Glossary: "Wiadomość agenta: Komunikat przesłany bezpośrednio między Agentami w ramach Runu." The "overmind" Skill lets an Agent write to other Agents (ADR 0027). Agents see only their current Workspace (ADR 0014), so messages never cross Workspaces. A message body can be large (a plan, a diff), so the payload lives in an Artifact and the message holds a reference (`payloadRef`) unless it is short.

## 3. Scope (in)

- Contract `AgentMessage`, `SendAgentMessageInput`, event `agent.message.sent`.
- Domain rules: addressing, size, correlation, thread depth, rate limit calculation.
- Table `agent_messages`, repository port and SQLite adapter.

## 4. Out of scope

- Send and receive use cases and delivery into a CLI: `OVE_AGENT012`. Reports to Chief: `OVE_AGENT014`. Artifact storage: DATA.

## 5. Detailed requirements

1. Contract (strict): `{ id: EntityId<'amg'>, runId: EntityId<'run'>, workspaceId, sender: { agentId }, recipient: { agentId } | { chief: true } | { broadcast: 'run' }, kind: 'request'|'reply'|'info'|'handoff', subject?: string<=120, body?: string<=2000, payloadRef?: { artifactId, mediaType, bytes, sha256 }, correlationId: EntityId<'cor'>, inReplyTo?: EntityId<'amg'>, createdAt, deliveredAt?, readAt? }`. Exactly one of `body` and `payloadRef` is required (`body` for short text, `payloadRef` above 2000 characters, max artifact size 1 MiB for messages).
2. `correlationId` groups a conversation; a `reply` MUST carry `inReplyTo` and inherit the `correlationId`; a `request` creates a new one (generated by the engine, not by the sender).
3. Addressing rules (pure `canSend(sender, recipient, ctx)`): sender and recipient must be participants of the same Run; broadcast only to Agents active in the Run; messages to Chief are always allowed; messages to the Owner are NOT an Agent Message (use a result or approval card). Sender equal to recipient is rejected.
4. Limits: max thread depth 20 messages per `correlationId`; max 30 messages per Agent per minute and 500 per Run (configurable); exceeding returns `agent.message_rate_limited` (429, retryable true with `retryAfterSeconds`).
5. Message text is treated as `agent` trust content (OVE_SEC004): the repository stores it as is (after secret redaction by the use case), and it is NEVER interpreted as an instruction by engine code. Delivery to another Agent wraps it as fenced data (`OVE_AGENT012`).
6. Table `agent_messages(id PK, run_id, workspace_id, sender_agent_id, recipient_kind, recipient_agent_id NULL, kind, subject, body, payload_artifact_id NULL, payload_sha256 NULL, correlation_id, in_reply_to NULL, created_at, delivered_at NULL, read_at NULL)` with indexes `(run_id, created_at)`, `(recipient_agent_id, read_at)`, `(correlation_id, created_at)`. Rows are append-only apart from `delivered_at/read_at`.
7. Repository port: `append`, `getById`, `listByRun(runId, page)`, `listThread(correlationId)`, `listUnreadFor(agentId, runId)`, `markDelivered(ids, at)`, `markRead(ids, at)`, `countSince(agentId, since)` (for the rate limit).
8. Error codes added to `agent.errors.ts` by proposal to AGENT001's owner file: `agent.message_not_allowed` (403, audit), `agent.message_too_large` (413), `agent.message_rate_limited` (429), `agent.message_thread_too_deep` (422). Until merged this task declares them in `packages/contracts/src/errors/agent-message.errors.ts` (area code `agent`, new file, no conflict).

## 9. Security and safety

Agent-to-agent messages are a lateral channel for prompt injection and for smuggling instructions between Agents with different permission profiles. Rules: cross-Run and cross-Workspace messaging impossible by construction; content is data; size and rate limited; no message can carry a permission, rule or configuration change (only typed requests via other use cases can). Secrets are redacted before storage. Audit is not needed per message, but rate-limit and not-allowed refusals are logged and audited.

## 10. Errors and edge cases

- Recipient Agent finished or archived: `agent.message_not_allowed`.
- Payload artifact missing or checksum mismatch at read: `data.corrupt_artifact`.
- Duplicate send (same sender, `clientMessageId`): handled by `OVE_AGENT012` idempotency.
- Reply to a message from another Run: rejected.
- Broadcast in a Run with one Agent: rejected as not allowed.

## 11. Acceptance criteria

- [ ] `canSend` rejects cross-Run, cross-Workspace, self and finished-recipient cases.
- [ ] Rate limit and thread depth limits return the specified codes.
