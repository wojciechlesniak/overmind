# OVE_DS039: ui-kit generators: token CSS emitter, barrel generator and new-component scaffold script

## 1. Summary

Provide the three generators that make parallel work on `packages/ui-kit` conflict-free: (1) a token pipeline that turns typed `*.tokens.ts` source files into one `tokens.css` plus typed TypeScript references, (2) a barrel generator that writes `src/index.ts` from the component folders, and (3) a `new:component` scaffold script that creates a component folder with story, test and CSS skeletons that follow the conventions of OVE_DS001.

## 2. Context

CONVENTIONS section 5.3 requires that shared aggregators are generated, never hand-edited (OVE_ARCH009). The ui-kit has dozens of tasks adding tokens and components at the same time, so the token CSS, the TS token objects and the barrel are generated from per-task files. The inventory (`COMPONENT-INVENTORY.md` section A intro) says tokens are `--om-*` CSS custom properties mirrored as a typed TS object in `packages/ui-kit/src/tokens`; this task builds that mirror mechanically so the two can never drift (DRY: one definition).

## 3. Scope (in)

- `defineTokens()` helper and the `TokenGroup` type.
- `scripts/build-tokens.ts`, `tokens:build` and `tokens:check` scripts; output `src/tokens/generated/tokens.css` (committed, `@generated` banner) and `src/tokens/generated/tokens.ts`.
- `scripts/build-barrel.ts`, `barrel:build` and `barrel:check`; output `src/index.ts` (committed).
- `scripts/new-component.ts` and `templates/component/*.tpl`, script `new:component <group> <Name>`.
- Unit tests for all three using temp-directory fixtures.

## 4. Out of scope

- The actual token values (OVE_DS002, OVE_DS003, OVE_DS004, OVE_DS006, OVE_DS007).
- Theme root and base CSS: OVE_DS008.
- Wiring `tokens:check` and `barrel:check` into root CI: OVE_SETUP006 (this task only provides the scripts and states the CI commands).
- Icon registry generation: OVE_DS009 owns its own registry (SVG sources are hand-written TSX, no generator).

## 5. Detailed requirements

**5.1 Token source format**
1. Every token file is `packages/ui-kit/src/tokens/<group>.tokens.ts` and default-exports the result of `defineTokens(groupName, values)`:
```ts
type TokenName = `--om-${string}`;
interface TokenGroup { readonly name: string; readonly values: Readonly<Record<TokenName, string>>; readonly layer?: 'tokens' }
export function defineTokens<const V extends Record<TokenName, string>>(name: string, values: V): TokenGroup & { readonly ref: TokenRefs<V>; readonly raw: V };
```
2. `ref` maps each CSS variable to a camelCase key holding `'var(--om-color-bg-app)'` (`--om-color-bg-app` -> `colorBgApp`), typed through a template-literal `CamelCase` type, so TS code (canvas, tests) can write `style={{ background: tokens.colorBgApp }}`. `raw` holds the literal values for tests (contrast checks) and for places where a literal is required (canvas SVG gradients that cannot use `var()` inside `stop-color` in some contexts).
3. A token value may reference other tokens with `var(--om-...)` and may use `color-mix()`; it may NOT contain a raw colour literal unless the file is in `src/tokens/` (the only place literals live).

**5.2 Token build**
4. `scripts/build-tokens.ts` discovers `src/tokens/*.tokens.ts` (alphabetical), imports them with `tsx`/`vite-node`, and validates: (a) every key matches `/^--om-[a-z0-9]+(-[a-z0-9]+)*$/`; (b) no duplicate key across files (error names both files and the key); (c) every `var(--om-x)` reference resolves to a defined key in any file (error lists unresolved refs and the file); (d) no empty values; (e) no reference cycles (depth-first check).
5. Emits `src/tokens/generated/tokens.css`:
```css
/* @generated by scripts/build-tokens.ts - do not edit */
@layer om.tokens {
  :root, [data-om-theme] {
    /* colors.tokens.ts */
    --om-color-bg-app: #0A0710;
    ...
  }
}
```
Order: files alphabetical, keys in definition order, a comment per file. Output is byte-stable (CI `tokens:check` regenerates in a temp dir and compares).
6. Emits `src/tokens/generated/tokens.ts` exporting `tokens` (merged `ref` of all groups), `tokenValues` (merged `raw`) and the union type `TokenName`.
7. `src/tokens/index.ts` re-exports `defineTokens`, `tokens`, `tokenValues` (this is the `@overmind/ui-kit/tokens` entry). `src/theme/foundation.generated.css` (see item 8a) already imports `../tokens/generated/tokens.css`, so this task creates `src/tokens/generated/tokens.css` (empty banner at first) and edits no other task's file.
8a. Foundation CSS aggregation: the same `tokens:build` run also writes `src/theme/foundation.generated.css` (banner `@generated`): first `@import '../tokens/generated/tokens.css';`, then one `@import` per `src/<group>/<NN>-<name>.foundation.css` file (regex `^[0-9]{2}-[a-z0-9-]+[.]foundation[.]css$`), sorted by file name, deduplicated, relative paths. Convention: `10-fonts` (OVE_DS004), `20-motion` (OVE_DS007), `30-base` (OVE_DS008); a new global CSS file needs only the right file name. `tokens:check` compares this file too. Add the file to `owns` (done) and a test with two fixture foundation files.
9. Dark/light: the selector `:root, [data-om-theme]` keeps room for a future `[data-om-theme="light"]` override file `theme.light.tokens.ts` (not created; open question 4 of the inventory). The generator supports an optional `selector` field on a group for that purpose.

**5.3 Barrel build**
9. `scripts/build-barrel.ts` scans `src/<group>/<Component>/index.ts` for groups in an allowlist (`actions, avatars, badges, forms, icons, indicators, labels, lists, navigation, overlays, surfaces, theme, typography, shell, chat, data, canvas, wizard`) and writes `src/index.ts`:
```ts
// @generated by scripts/build-barrel.ts - do not edit
export * from './actions/Button';
...
export { tokens } from './tokens';
```
10. Rules: alphabetical by group then folder; skips `internal`, `testing`, `__guards__`, `types`, `tokens` internals; fails when two folders export the same identifier (it parses `export {..}` / `export type {..}` lists with the TypeScript compiler API, no regex); fails when a folder `index.ts` has a default export or `export *` (explicit named exports only, so the public API is greppable).
11. `barrel:check` regenerates in memory and compares with the committed file.

**5.4 Component scaffold**
12. `pnpm --filter @overmind/ui-kit new:component <group> <Name>` validates the group against the allowlist and `Name` as PascalCase, refuses if the folder exists, and creates: `index.ts`, `<Name>.tsx` (forwardRef, `data-om="<Name>"`, rest-props spread, props interface), `<Name>.module.css` (`@layer om.components { .root { } }`), `<Name>.stories.tsx` (Default + Matrix using `storyMatrix`), `<Name>.test.tsx` (renders, axe check, forwards ref, spreads rest props), then runs `barrel:build`. Templates live in `packages/ui-kit/templates/component/` as `.tpl` files with `{{Name}}`, `{{group}}`, `{{kebab}}` placeholders (simple string replace, no template dependency).
13. The scaffold never overwrites files and prints the next-steps checklist (props table, variant matrix, states, a11y, visual test).

## 7. Reuse

OVE_DS001 conventions (folder layout, internal utilities, story matrix helper). TypeScript compiler API (already a dev dependency) for barrel parsing; `tsx` or `vite-node` for running scripts (whichever OVE_SETUP008 allows; no new runtime dependency).

## 8. Architecture and code placement

Dev tooling inside `packages/ui-kit/scripts/` (not shipped). Pure functions (`collectTokens(files)`, `renderCss(groups)`, `renderBarrel(entries)`) are separated from file I/O so they are unit-testable; the CLI wrappers only read and write files (SRP, DIP: I/O is injected via a tiny `FsLike` interface in tests).

## 9. Security and safety

- Scripts only read and write inside `packages/ui-kit/` (resolve all paths against the package root and reject any `..` escape; refuse symlinks that resolve outside the package). They never execute strings from token values.
- Token values are inserted into CSS verbatim: the generator rejects values containing `;`, `{`, `}`, `/*`, `*/`, `url(` and `@import` so a malicious or accidental token cannot break out of its declaration or load remote resources (offline app, CSP).
- The scaffold escapes placeholders strictly (`Name` is validated as `^[A-Z][A-Za-z0-9]+$`) so a crafted name cannot create paths or code.
- Generated files carry the banner and CI fails when they are stale, so nobody can smuggle changes into a generated file.

## 10. Errors and edge cases

- Duplicate token key in two files: build fails, message lists both file names and line numbers of the definitions.
- Unresolved `var(--om-missing)`: build fails.
- A `*.tokens.ts` file without a default export or with a non-`defineTokens` result: build fails with the file name.
- Barrel: two components exporting `Pill`: fails naming both folders. Folder without `index.ts`: warning, skipped. Empty groups: skipped.
- `new:component actions button`: rejected (not PascalCase). `new:component nope Button`: rejected with the group list.
- Running twice produces no diff (idempotent).

## 11. Acceptance criteria

- [ ] A fixture token file produces the exact expected `tokens.css` and `tokens.ts` (golden files in `scripts/__fixtures__`).
- [ ] Duplicate keys, unresolved references, cycles, forbidden characters (`;`, `url(`, `@import`) each fail with a specific message (tests).
- [ ] `tokens:check` and `barrel:check` exit non-zero when the committed output is stale and zero otherwise.
- [ ] `src/index.ts` is generated and contains explicit named exports only; a default export or `export *` in a component `index.ts` fails.
- [ ] `new:component forms Foo` creates five files that compile, pass the generated test and show a Default and a Matrix story; the barrel contains `Foo` afterwards.
- [ ] Running any script twice leaves `git status` clean.
- [ ] `tokens` is importable from `@overmind/ui-kit/tokens` and `tokens.colorBgApp` equals `'var(--om-color-bg-app)'` once OVE_DS002 lands (covered by that task's test; here by a fixture).

## 12. Test plan

Unit tests in `scripts/__tests__/`: `collectTokens.test.ts`, `renderCss.test.ts` (golden), `validateTokens.test.ts` (each failure), `renderBarrel.test.ts` (ordering, duplicate detection with a compiler-API parse of `export { A, B as C }` and `export type`), `newComponent.test.ts` (temp dir, placeholder substitution, refuses overwrite). Run: `pnpm --filter @overmind/ui-kit test scripts`. CI commands: `pnpm --filter @overmind/ui-kit tokens:check && pnpm --filter @overmind/ui-kit barrel:check`.

## 13. Parallelization notes

Runs in parallel with OVE_DS002..OVE_DS007 once OVE_DS001 is merged, but token tasks need `defineTokens` to merge; they may start by writing their `*.tokens.ts` against the signature in 5.1 (a stub of `defineTokens` is acceptable locally, the real one lands here first). Hotspots: `src/index.ts` and `tokens.css` are generated: after a rebase conflict in them, regenerate (`pnpm --filter @overmind/ui-kit tokens:build && pnpm --filter @overmind/ui-kit barrel:build`) instead of resolving by hand.
