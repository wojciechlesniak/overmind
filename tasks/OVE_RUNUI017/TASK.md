# OVE_RUNUI017: Build 'Eksportuj raport': options dialog, redacted engine report, save to file

## 1. Summary

The export flow of the Run header button: choose format (Markdown or JSON) and sections (summary, trace, activity, tool calls, usage, reproducibility), have the engine build a redacted report, and save it through the native file dialog. The report never contains secrets, raw outputs or paths outside the Workspace.

## 2. Context

Overmind is a desktop app (Tauri + React + TypeScript) in which one Owner runs teams of AI Agents. A Workflow is an executable program (ADR 0002): the editor only creates and shows the graph, the engine runs it. Every Run pins an immutable Workflow Version; editing creates a new Version and never changes a running Run. Visibility (PUBLICZNY / PRYWATNY, ADR 0028) is always shown as a word. The UI talks only to the engine gateway through `api-client` (CONVENTIONS section 6). UI copy in the mock is Polish; code uses i18n keys with EN default and PL first translation (ARCH011). The Activity view ('Runy i Activity' tab, Main nav item Workflow, second tab) is the observability surface of SPEC 15: who did what and when, which Tool was called with what result, usage per Provider, model, Agent, Run and Workspace (CLI limits as the CLI reports them, 'wg CLI'), reproducibility of a Run (graph, Agent, Skill and model versions), live view with filters by Run and Agent, redaction of secrets and personal data, report export. SPEC 15: 'eksport raportów'. The report is generated by the engine (single redaction point, SEC003) and returned as text/bytes; the desktop saves it where the Owner chooses (OS save dialog through the desktop bridge, a platform interface from ARCH012, `lib:desktop-save-file`). Reports are also what the Owner shares for support, so redaction must be strict.

## 3. Scope (in)

- `ExportDialog` and `useExportReport`.
- Section and format options with sensible defaults and size estimate.
- Save flow with the native dialog, success and failure handling.
- Report preview (first 40 lines, read-only) before saving.

## 4. Out of scope

- Report generation in the engine (WFRT/ENGINE area; route `api:runs.export`).
- Native dialog implementation (Tauri shell).

## 5. Detailed requirements

1. Dialog: title 'Eksportuj raport Runu #14'; format segmented: 'Markdown (.md)' (default) / 'JSON (.json)'; sections as checkbox rows: 'Podsumowanie' (always on, disabled), 'Ślad Runu', 'Activity (zdarzenia)', 'Dziennik narzędzi (podsumowania, bez wyników)', 'Zużycie wg CLI', 'Odtwarzalność (wersje)'; defaults: all on except tool calls detail; a separate switch 'Dołącz podsumowania wyników narzędzi' (off).
2. Request: `runs.export { runId, format, sections[], includeToolResultSummaries }` -> `{ filename, mime, sizeBytes, content (text, max 5 MiB) | downloadRef, redactionCount, truncated }`; the UI shows 'Ukryto N wartości w raporcie' and, if truncated, 'Raport został skrócony (limit 5 MiB)'.
3. Preview: first 40 lines in a read-only `pre`-like block (mono 12, text only), with the 'Skopiuj' button; the preview exists to make the Owner aware of what is shared.
4. Save: `lib:desktop-save-file({ suggestedName: 'run-14-dostarczanie-funkcji-2026-10-13.md', content, mime })` opens the OS dialog; the Owner picks the location; the UI never constructs paths. Cancel in the OS dialog is a no-op (no error).
5. Suggested file name: slug of Workflow name + run number + date, ASCII only, max 80 chars.
6. Errors: `wfrt.run_not_found`, report too large, engine failure -> inline message with retry; save failure -> toast 'Nie udało się zapisać pliku'.
7. A note under the options: 'Raport nie zawiera haseł, tokenów ani pełnych wyników poleceń.' (true by contract); the engine audits the export (`run.exported` audit action).
8. Export of a live Run is allowed and labelled in the report as 'stan na <time>'.
9. Busy state with spinner while the engine builds; cancel button aborts the request.

## 9. Security and safety

The UI is a thin client: it never reads files, the database or CLIs, and every mutation goes through the gateway, which re-validates everything server-side (client-side checks are convenience only). Text coming from Agents, Skills, repositories or Run output is data: render it as plain text (no `dangerouslySetInnerHTML`, no Markdown with raw HTML, no link auto-navigation), truncate with a `title`, and never use it as an i18n key, a route or a CSS value. The UI cannot extend permissions: it shows the intersection computed by the engine and offers only narrowing or an Access Request. Mutating calls send an idempotency key and handle `409` and `423` (paused) results as typed errors. Failures fail closed: when a check cannot be performed the control is disabled with a visible reason. Redaction is performed once, server-side, before the content ever reaches the UI; the UI never builds report content from raw data. The save path comes only from the native dialog. Content is treated as text (no HTML rendering of the preview). The export is audited by the engine.

## 10. Errors and edge cases

- Report preview contains Markdown/HTML from Agents: shown in a text block, never rendered.
- File name collision: handled by the OS dialog.
- Engine returns `downloadRef` for big content: the UI streams to the file via the bridge (bounded to 5 MiB; larger refused).
- Cancelling the OS dialog leaves the dialog open.
