# OVE_ENGINE028: Agent token lifecycle

## 1. Summary

The "overmind" Skill inside an agent's sandbox talks to the same gateway (ADR 0027) with a narrow, short-lived credential: an agent token bound to one Run, one Agent and one Workspace. This task defines minting, validation scope, expiry and revocation so an agent can report progress, file Access Requests, message peers and record Decisions, and nothing else.

## 2. Context

SEC005 G5: `ovm_at_` + 256 bits, minted per (Run, Agent) by the engine when it starts the Agent environment, delivered through an environment variable only visible to that environment, scope `agent`, bound to `runId`/`agentId`, expires when the Run ends or after 24 h, revoked on cancel/complete and on engine restart (new token injected at resume). It cannot read other Runs, call Owner routes, mint tokens, or subscribe to other Runs' events. Delivery into the sandbox is BOX/PROV (they call the issuer); the transport from inside the container to the host socket is also theirs (flagged in report as a cross-area need).

## 3. Scope (in)

- `AgentTokenIssuer` port, in-memory token registry (hash only), validation into `GatewayCaller{kind:'agent'}`, revocation on events, expiry sweeps.

## 4. Out of scope

- Injecting the token and the socket/relay into the container (BOX/PROV). The agent-facing routes (WFRT, AGENT, PERM, DEC, CHAT each own theirs, scope `agent` + `agentBinding`). The Skill text (SKILL).

## 5. Detailed requirements

1. Port: `mint({ runId, agentId, workspaceId, ttlMs? }): Result<{ token: string; expiresAt: string }>`; `revokeRun(runId)`, `revokeAgent(agentId)`, `revokeAll()`. Token format `ovm_at_<43 chars base64url>`; generated by `SecureRandom`.
2. Storage: in memory only: `Map<sha256(token), { runId, agentId, workspaceId, issuedAt, expiresAt, revoked }>`; never persisted, so engine restart revokes everything (recovery re-mints for resumed Runs via PROV/WFRT calling `mint` again). Max 50 live tokens (parallel Agents limit 10 x margin); `mint` beyond returns `internal.limit_reached`.
3. Validation (`authenticate` extension): after the owner-token check fails, try agent tokens with the same constant-time hash compare; success yields `GatewayCaller { kind:'agent', runId, agentId, workspaceId, local:false }`. Expired or revoked tokens are indistinguishable from unknown ones (same 401).
4. Lifetime: default TTL 24 h; ends earlier on events `run.completed|failed|cancelled` and `agent.stopped` (subscription in the module), and when Global Pause is toggled: tokens stay valid but the gateway rejects mutating calls from agents while paused (`perm.paused`, enforced by the pipeline hook `pauseGate` reading the PauseState read port; flagged need `port:PauseStateReader`).
5. Run-binding checks (with ENGINE013's `agentBinding`): ids in params/body that differ from the token's Run/Workspace -> 404; an agent token used on `events.subscribe` receives only its Run's events (ENGINE017 filter uses the caller fields).
6. The agent API surface is limited to routes whose contract `scope` includes `agent`; ARCH008 forbids `experimental` stability and `expandsPermissions` on them (startup assertion in ENGINE013). Agents cannot call token or config routes.
7. Rate limits per Run (ENGINE014: 20 req/s) and body cap 256 KiB for agent routes (route metadata) to bound abuse by a prompt-injected agent.
8. Audit: mint and revoke events (`agent_token.minted`, `agent_token.revoked`) as persisted audit events with ids only; never the token. Agent calls are audited by ENGINE016.
9. Token delivery contract for BOX/PROV: the issuer returns the token to the caller in memory; the caller injects it as env `OVERMIND_API_TOKEN` (name fixed here) together with `OVERMIND_API_SOCKET` (the in-sandbox path of the forwarded socket) and `OVERMIND_RUN_ID`; it must not write the token to files in `/work`, to logs, or to the herdr command line (ps-visible). This is stated in the doc `docs/security/gateway-auth.md` addendum via a proposal to SEC005 (file owned by SEC005).
10. Key rotation: `revokeAll()` is called at engine start and on Owner token rotation; sandboxes get fresh tokens through resume.

## 9. Security and safety

Agents are potentially malicious or prompt-injected (SR-24, SR-31): the token is the minimal credential, memory-only, short-lived, Run-bound, uniform failures, no minting by agents, no Owner routes, no cross-Run reads, limited rates and sizes. Paused state blocks agent mutations. A token that leaks from a sandbox is useless after the Run ends or the engine restarts. Residual risk: token visible to all processes inside that agent's container (documented; the env var is not forwarded to other containers).

## 10. Errors and edge cases

- Run cancelled while a request is in flight: request finishes or is rejected after revocation; no new requests.
- Engine restart: all tokens gone; agents get 401 until resumed Runs receive new ones; the Skill retries with backoff for 60 s then reports `engine_unavailable` to the user in the CLI.
- Clock jump: expiry uses `Clock.now`; monotonic not required, 24 h tolerance.
- Token minted for a Run that is already terminal: rejected `conflict`.

## 11. Acceptance criteria

- [ ] SEC005 tests 8 and 9 pass (matrix, expiry, Run completion, cross-Run subscription, minting route absent for agents).
- [ ] Token never appears in logs, events or persisted tables (scan).
- [ ] After `run.completed` the token yields 401.
- [ ] Agent calling an Owner route gets 403; reading another Run's resource gets 404.
- [ ] Engine restart invalidates all agent tokens.
- [ ] 51st mint returns the limit error.

## 12. Test plan

Unit tests (store, expiry with `FakeClock`, revoke on events); gateway-under-test security suite; property test: random tokens never validate. Commands: `pnpm test:security:gateway`, `pnpm vitest run packages/gateway/src/agent-auth`.
