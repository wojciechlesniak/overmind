# OVE_ARCH009: Implement extension-point conventions, generators and the ownership lint

## 1. Summary

Make "add a file, edit nothing shared" real. This task defines and implements the exact conventions and generators for the seven extension points of CONVENTIONS section 5 (UI feature manifests, i18n namespaces, gateway route modules, contract barrels, port barrels, event types, DB migrations, plus composition modules) and the ownership lint that fails a branch editing files outside its task's `owns` paths.

## 2. Context

Dozens of agents work in parallel worktrees (CONVENTIONS section 5). Shared aggregator files (route tables, nav lists, barrels, wiring) are the classic conflict hotspots. The conventions below replace them with auto-discovered per-feature files and git-ignored generated aggregators. The ownership lint enforces rule 2 mechanically.

## 3. Scope (in)

- `defineFeature()` and manifest collection for the desktop UI (`feature.manifest.ts`).
- `defineRouteModule()` for gateway routes and its registration helper.
- Generator `pnpm gen` (`tools/gen/`): barrels (`index.generated.ts`) for contracts folders, ports, events, errors, id prefixes, config sections; route index; module index for `apps/engine` composition; migration manifest; i18n namespace index.
- Migration naming validator.
- Ownership lint `pnpm ownership:check`.
- Documentation `docs/architecture/extension-points.md` (one section per extension point with a copy-paste template).

## 4. Out of scope

- i18n runtime and key lint: `OVE_ARCH011`. Contract pipeline: `OVE_ARCH008`. DI semantics: `OVE_ARCH006`. Migration runner and DB: DATA. Claim/worktree scripts and the task front-matter linter: `OVE_SETUP013` (it may call `ownership:check`).
- The shell that renders nav items and routes from manifests: SHELL area (consumes `collectFeatures`).

## 5. Detailed requirements

1. **General generator rules.** `pnpm gen` is idempotent, deterministic (sorted by path), fast (< 5 s), writes only `*.generated.ts` / `*.generated.json` files that are git-ignored and prefixed with `// GENERATED by tools/gen, do not edit`. It runs automatically before `dev`, `typecheck`, `test`, `build` (`pre*` scripts) and in CI first. Generated files are never committed, so they never conflict. A `--check` mode fails if a committed file contains the generated header.
2. **Contract barrels.** For each directory `packages/contracts/src/<entity>/` generate `index.generated.ts` with `export * from './<file>'` for every `*.ts` not matching `*.test.ts`, `*.generated.ts`, `_*.ts`. Root `packages/contracts/src/index.generated.ts` uses flat `export * from './<entity>'` for every entity folder (names are therefore globally unique; use entity-prefixed names such as `PauseState`); the generator fails on duplicate export names across entities (`GEN_DUPLICATE_EXPORT` with both files). Entity folder and file names: kebab-case; one file per schema group, named `<noun>.schema.ts`, API routes `<resource>.routes.ts`, events in `events/<event-type>.event.ts` (one file per event type), errors `errors/<area>.errors.ts`, config sections `config/sections/<area>.config.ts`.
3. **Ports barrel.** `packages/application/src/ports/index.generated.ts` exports all `<PortName>.ts` (PascalCase, one port per file, must export an interface and a `...Token`). Lint: file name equals the primary exported interface name.
4. **Events.** One file per event type under `packages/contracts/src/events/<dotted-type-kebab>.event.ts` exporting `defineEvent(...)` (ARCH010). Generator produces `events/registry.generated.ts` mapping type string to schema and `EventType` union.
5. **UI feature manifest.** File `apps/desktop/src/features/<feature>/feature.manifest.ts`, default export:
   ```ts
   export default defineFeature({
     id: 'board',                          // kebab-case, equals the folder name
     titleKey: 'board:nav.title',           // i18n key in this feature's namespace
     namespaces: ['board'],                // i18n namespaces to load (files locales/<lang>/board.json)
     routes: [{ path: '/board', element: () => import('./routes/BoardRoute'), meta?: {...} }],   // lazy
     nav: [{ id: 'board', area: 'rail' | 'tab' | 'settings-tab', labelKey: 'board:nav.label', icon: 'IconName', order: 40, parent?: 'workflow', badge?: () => import('./badge') }],
     statusItems?: [{ id, slot: 'top-bar'|'tray', order, component: () => import(...) }],
     commands?: [{ id, labelKey, run }],
     requiresCapabilities?: ['api:board.list'],
   });
   ```
   `defineFeature` validates with zod at import time in dev. Collection: `collectFeatures(modules: Record<string, {default: FeatureManifest}>)` in `apps/desktop/src/shared/extension/collect-features.ts`: checks unique `id`, unique `path` per route, valid `parent`, nav `order` ties (stable by id), folder-name = id. The SHELL area calls `collectFeatures(import.meta.glob('../features/*/feature.manifest.ts', { eager: true }))` and builds rail/tabs/routes. Route paths are namespaced under `/` + feature conventions defined in SHELL; this task only validates uniqueness.
6. **i18n namespace files** (convention only): `apps/desktop/src/locales/<lang>/<feature>.json` where `<lang>` in `en`, `pl`, `en-XA` (pseudo, generated); engine strings `packages/<pkg>/locales/<lang>/<ns>.json`. Generator writes `apps/desktop/src/locales/index.generated.ts` using `import.meta.glob('./*/*.json')` equivalents (lazy). Details in ARCH011.
7. **Gateway route modules.** One file per capability `packages/gateway/src/routes/<area-lowercase>/<name>.route.ts`, default export:
   ```ts
   export default defineRouteModule({
     route: pauseGlobalSetRoute,                          // RouteContract from contracts (ARCH008)
     requires: { pause: SetGlobalPauseToken },            // use case tokens (ARCH006)
     handle: ({ pause }) => async ({ body, caller, ctx }) => {   // returns Promise<Result<Response>>
       return pause.execute({ paused: body.paused, actor: caller });
     },
   });
   ```
   `defineRouteModule` is in `packages/gateway/src/route-module/`. Handlers receive validated input (params/query/body typed from the route), `caller` (`{ kind: 'owner'|'agent'|'channel', channel?, runId?, agentId? }`), and `ctx` (`signal`, `requestId`, `logger`). They return `Result`; they never write to the transport, never catch-all, never read env. Generator emits `routes/index.generated.ts` listing all route modules; the ENGINE gateway registers them and resolves `requires` through the composed engine; duplicates of `(method, path)` are rejected at generation and at startup.
8. **Composition modules.** `apps/engine/src/composition/modules/<area>.module.ts` (ARCH006) listed by `modules.generated.ts`.
9. **Migrations.** File `packages/adapters/sqlite/migrations/V<YYYYMMDDHHmm>__<TASKID>__<snake_name>.sql`, example `V202610131530__OVE_PAUSE003__create_pause_state.sql`. Rules validated by `tools/gen/check-migrations.ts`: timestamp is 12 digits, valid date, not in the future by more than 1 day; `TASKID` matches `OVE_[A-Z]+[0-9]{3}` and exists in `tasks/`; name snake_case; unique version string; merged migrations are immutable (compare git history: a changed file whose version exists on `origin/main` fails with `MIGRATION_EDITED`); a migration may only create/alter objects whose names start with the task's area table prefix OR declare `-- owns-tables: a,b` header validated against the ownership map; no `DROP TABLE`/`DROP COLUMN` without header `-- destructive: <reason>` (security review item); each file header lists `-- task: OVE_X` and `-- tables:`. Version collisions when two agents choose the same minute are avoided by including `TASKID` in sorting tie-break (version, then task id) and by validation of uniqueness on version+task.
10. **Ownership lint** (`tools/ownership/check.ts`, `pnpm ownership:check [--task OVE_X] [--base origin/main]`):
    - Task id comes from `--task`, else from branch name `task/OVE_X`, else from the worktree folder name `../wt/OVE_X`.
    - Reads `tasks/<ID>/TASK.md` front matter `owns` (globs). Computes changed files with `git diff --name-status --find-renames <base>...HEAD` (including untracked staged files).
    - Allowed without `owns` match: `tasks/<ID>/**`, `tasks/_proposals/<ID>-*.md`, files colocated tests/stories/fixtures of an owned path (`**/*.test.ts`, `**/*.stories.tsx`, `**/__fixtures__/**`, `**/test/**` inside an owned directory), `pnpm-lock.yaml` and the `package.json` of an owned package (ASSUMPTION; a new dependency must also appear in `docs/dependencies.md`, checked by SETUP008).
    - Everything else is a violation `OWNERSHIP_OUTSIDE_OWNS` listing file and nearest owner (reverse lookup across all tasks' `owns`) with advice to write `tasks/_proposals/<ID>-<name>.md`. Edits to a path owned by another task get `OWNERSHIP_FOREIGN_OWNER`.
    - Also checks: no two tasks' `owns` globs overlap (`pnpm ownership:overlap`, used by the linker, reports pairs), generated files not committed, task status flow.
    - Exit codes: 0 ok, 1 violations, 2 usage error. Output machine-readable with `--json`.
11. **Documentation** has a recipe per extension point: "Add a UI feature", "Add an API endpoint", "Add an event", "Add a port", "Add a migration", "Add a config section", "Add translations", each with the exact files to create and the commands to run.
12. ## 8. Architecture and code placement

Tools only in `tools/gen/`, `tools/ownership/`. Runtime helpers: `apps/desktop/src/shared/extension/{define-feature.ts,collect-features.ts}` (browser-safe, zod) and `packages/gateway/src/route-module/{define-route-module.ts,types.ts}`. These helpers hold no business logic (SRP). Each generator is a small plugin implementing `Generator { name, inputs: Glob[], run(ctx): GeneratedFile[] }` so new extension points add a generator file (OCP).

## 9. Security and safety

The ownership lint is a control against agents (or prompt-injected agents) silently editing security-critical files: edits to `tasks/CONVENTIONS.md`, `docs/architecture/boundaries.json`, CI workflows, lockfiles, `packages/application/src/ports/**` of other areas are blocked unless the task owns them. Generators never execute project code except importing declared contract modules in a restricted `vm`-free Node child process with no network; generated output is plain TypeScript. Route modules cannot register routes outside their contract's `scope`; the gateway rejects a route whose `scope` includes `agent` unless the module path is under an allowlisted area (reviewed by SEC). Migration lint flags destructive statements.

## 10. Errors and edge cases

- Branch name not matching `task/<ID>`: require `--task`; in CI the PR title/branch is passed.
- Task with `owns: []` (docs/decision kinds): may edit only `tasks/<ID>/**` and proposals; anything else fails.
- File renamed from foreign path into owned path: both sides are checked.
- Generated barrel for an empty folder: file with `export {}`.
- Windows path separators normalised.
- Migration timestamp collisions across agents: allowed if the task ids differ; warn.
- Manifest module that throws on import: collector reports feature folder and error, build fails.

## 11. Acceptance criteria

- [ ] `pnpm gen` produces all barrels/indices deterministically; a second run changes nothing; generated files are git-ignored and `gen --check` rejects committed ones.
- [ ] Duplicate export names, duplicate route `(method, path)`, duplicate feature ids/paths and invalid migration names each fail with the documented error code (fixtures).
- [ ] `collectFeatures` validates and orders manifests (rail order, parent tabs) in unit tests.
- [ ] A route module fixture is registered by the generator and its `requires` tokens are listed in the generated index.
- [ ] `ownership:check` reports edits outside `owns`, accepts colocated tests/stories and own task folder, and names the foreign owner.
- [ ] `ownership:overlap` finds overlapping `owns` globs across tasks (fixture) and returns exit 1.
- [ ] Editing a merged migration fails with `MIGRATION_EDITED` in a simulated git repo.
- [ ] `docs/architecture/extension-points.md` has all seven recipes.

## 14. Open questions and assumptions

- ASSUMPTION: lockfile and `package.json` edits in an owned package are permitted by the ownership lint; any other root-level file is not.
- ASSUMPTION: generated aggregators are git-ignored (no committed generated code) to remove conflicts; CI and dev scripts always run `pnpm gen` first.
- Open: Storybook story discovery uses glob (`*.stories.tsx`) so needs no generator.
