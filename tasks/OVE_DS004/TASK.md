# OVE_DS004: Typography tokens and self-hosted fonts (Bricolage Grotesque, JetBrains Mono)

## 1. Summary

Vendor the two typefaces of the product as self-hosted, subsetted `woff2` files (no Google Fonts at runtime), define `@font-face` rules and the font-family tokens, and define every named text style of the mocks (size, weight, letter-spacing, line-height, transform, default colour) as one typed table plus CSS variables. The `Text` component that renders them is OVE_DS005.

## 2. Context

Two families (`COMPONENT-INVENTORY.md` A.2): **Bricolage Grotesque** for UI (weights 400/600/700) and **JetBrains Mono** for labels, paths, statuses, tabs and numbers (400/500/600/700). The mocks load Google Fonts; the app is offline-capable and runs under a Tauri CSP, so both fonts are bundled (`font-src 'self'`, OVE_SETUP010). Both fonts are SIL Open Font License 1.1 (redistribution allowed with the licence text; list them in the NOTICE file, OVE_OSS001). Polish copy needs `latin-ext` (ą ć ę ł ń ó ś ź ż and capitals). Important fact for visual tests: the exported mock PNGs were rendered with a FALLBACK font (the build sandbox could not fetch Google Fonts, `VIEWS.md` "How to read"), so text widths in `design.png` differ from the real fonts by a few px; geometry and colours are authoritative.

## 3. Scope (in)

- Font files (4 woff2: Bricolage latin + latin-ext, JetBrains Mono latin + latin-ext), provenance file `FONTS.md` (upstream URL, version, SHA-256 of the source and of each woff2, licence), the reproducible build script `scripts/fonts/build-fonts.sh` (documented, not run in CI), and the verify test.
- `10-fonts.foundation.css` with the four `@font-face` rules (picked up by the foundation generator, OVE_DS039).
- Tokens `typography.tokens.ts`: families, size scale, weight scale, tracking scale.
- `textStyles.ts`: the typed table of named styles (5.3) and, through `defineTokens`, CSS variables `--om-text-<style>-font`, `--om-text-<style>-ls`, `--om-text-<style>-transform`, `--om-text-<style>-color`.
- Type specimen story listing all styles with sample copy and measured specs.

## 4. Out of scope

- The `Text` component and its CSS: OVE_DS005.
- Avatar initial sizes (they depend on avatar size): OVE_DS016.
- Hooking Polish/English copy: ui-kit has none.
- Preloading fonts in `apps/desktop/index.html`: OVE_SETUP009 (this task documents the two URLs to preload in `FONTS.md`).

## 5. Detailed requirements

**5.1 Font files**
1. Bricolage Grotesque: take the upstream variable TTF, pin axes with `fonttools varLib.instancer` to `opsz=14 wdth=100 wght=400:700` (the Google css2 URL used by the mocks serves the default optical size 14 and width 100, so this reproduces the mock's glyph shapes), then `pyftsubset` to two subsets and compress to woff2. JetBrains Mono: variable `wght` 400:700, same subsetting. Result: `Bricolage-latin.woff2`, `Bricolage-latin-ext.woff2`, `JetBrainsMono-latin.woff2`, `JetBrainsMono-latin-ext.woff2` in `src/typography/fonts/`. Size budget: each file <= 60 kB, total <= 200 kB (test).
2. Unicode ranges: latin `U+0000-00FF, U+0131, U+0152-0153, U+02BB-02BC, U+02C6, U+02DA, U+02DC, U+0304, U+0308, U+0329, U+2000-206F, U+20AC, U+2122, U+2191, U+2193, U+2212, U+2215, U+FEFF, U+FFFD`; latin-ext `U+0100-02BA, U+02BD-02C5, U+02C7-02CC, U+02CE-02D7, U+02DD-02FF, U+0304, U+0308, U+0329, U+1D00-1DBF, U+1E00-1E9F, U+1EF2-1EFF, U+2020, U+20A0-20AB, U+20AD-20C0, U+2113, U+2C60-2C7F, U+A720-A7FF`. A test (`fonts.test.ts`, uses `fontkit`-free parsing of the cmap through a tiny reader or a Node script run in the test with `fonttools` only when available; otherwise a committed JSON of covered code points generated by the build script) asserts that every Polish letter `ĄąĆćĘęŁłŃńÓóŚśŹźŻż`, `· … – — „ ” « » ‹ › ‰` and digits are covered by at least one subset of each family.
3. `@font-face` (in `10-fonts.foundation.css`, inside `@layer om.base`): `font-family: 'Bricolage Grotesque'` with `font-weight: 400 700`, `font-style: normal`, `font-display: swap`, `src: url('./fonts/Bricolage-latin.woff2') format('woff2')` and the unicode-range of item 2; same for `'JetBrains Mono'` (`font-weight: 400 700`). No `http(s)://` URL anywhere (test greps the CSS).
4. Fallback stacks (tokens): `--om-font-sans: 'Bricolage Grotesque', system-ui, -apple-system, 'Segoe UI', sans-serif;` and `--om-font-mono: 'JetBrains Mono', ui-monospace, SFMono-Regular, Menlo, monospace;` (a superset of the mock stacks `'Bricolage Grotesque', system-ui, sans-serif` and `'JetBrains Mono', monospace`).
5. Rendering settings (applied by OVE_DS008): `font-optical-sizing: none` (axis pinned), `font-variant-ligatures: none` on mono (paths and flags such as `->`, `!=`, `==` must show as typed; ASSUMPTION), `font-variant-numeric: tabular-nums` on `.mono*` styles, `-webkit-font-smoothing: antialiased`.
6. Symbols not in either font fall back to the system font: `⌘` (Kbd) and any Unicode glyph. The status glyphs `✓ ✗ ● ○ ◆ ▍ → ↔ ›` are NOT text any more (inventory E21): they become SVG (OVE_DS011/OVE_DS020), so the fonts need no symbol coverage.

**5.2 Scales (tokens)**
Sizes `--om-font-size-10, 11, 12, 13, 14, 15, 16, 17, 18, 20, 22, 24, 26, 32, 34` (px); weights `--om-font-weight-regular 400`, `-medium 500`, `-semibold 600`, `-bold 700`; tracking `--om-tracking-tight-xl -0.02em` (display/titles: -0.68px at 34px = -0.02em, -0.52px at 26px = -0.02em, -0.48px at 24px = -0.02em, -0.44px at 22px = -0.02em), `--om-tracking-title-22 -0.2px` (E7), `--om-tracking-node -0.2px`, `--om-tracking-label 0.08em`, `-label-wide 0.1em`, `-badge-outline 0.06em` (E17), `-badge-filled 0.1em`, `-node-tab 0.12em`, `-eyebrow-wide 0.1em`, `--om-tracking-normal 0`.

**5.3 Named text styles (exact table; `textStyles.ts` is the single source)**

Avatar initials (700, size = avatar size x ~0.38, line-height = avatar size) are defined by OVE_DS016, not here.
7. Uppercase is produced by `text-transform: uppercase` (source strings stay sentence case so Polish translations stay simple, inventory A.2 recommendation); screen readers read the original string. The `--om-text-<style>-transform` variable is `uppercase` or `none`.

**5.4 Token form.** For each style `<s>`: `--om-text-<s>-font: <weight> <size>px/<lh> var(--om-font-sans|mono)`; `--om-text-<s>-ls`; `--om-text-<s>-transform`; `--om-text-<s>-color` (only where a default colour exists). `textStyles` is exported typed as `Record<TextStyleName, TextStyleSpec>`; `type TextStyleName` is the key union (used by OVE_DS005).

## 8. Architecture and code placement

`packages/ui-kit/src/typography/` (assets + CSS) and `src/tokens/` (typed data). Font build tooling in `packages/ui-kit/scripts/fonts/` (developer-run, never in CI or the app). The table is data: adding a style is a new row plus one CSS rule in OVE_DS005 (OCP), and a test links the two.

## 9. Security and safety

ui-kit is presentation only: no network, filesystem, storage, `eval`, `new Function` or `dangerouslySetInnerHTML` anywhere (lint rule `react/no-danger` set to error in OVE_DS001). Every string arrives as a prop and is rendered as a React text node, never as HTML, so Agent, repository, document or Telegram content that an app shows through this component cannot inject markup. Colour is never the only carrier of meaning (state, Visibility, severity always come with a word or glyph, `docs/design/styl-wizualny.md` rules). The component takes no secrets and logs nothing (`console.*` is a lint error in `src/`).
Specific: supply chain. The vendored binaries are verified by SHA-256 in `FONTS.md` and a test recomputes them (a swapped font file fails CI). The build script downloads only from the pinned upstream release URLs and refuses other hosts; fonts are never fetched at app runtime (CSP `font-src 'self'`, no tracking via Google Fonts, important for an app that runs against private code).

## 10. Errors and edge cases

- Font fails to load: `font-display: swap` shows the fallback stack, layout uses explicit line-heights so nothing jumps by more than the glyph width difference.
- A missing glyph (for example Polish `ł` absent from a subset): the coverage test fails the build.
- File size over budget: test fails, fix by re-subsetting.
- Upstream release changes: hashes in `FONTS.md` no longer match the rebuild; updating fonts is a deliberate task (new hashes reviewed).
