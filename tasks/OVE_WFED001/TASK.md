# OVE_WFED001: Create the workflow-editor feature skeleton, layering rules and i18n namespaces

## 1. Summary

Creates the folder layout of `apps/desktop/src/features/workflow-editor/`, a test that enforces which folder may import what, and the document `docs/frontend/workflow-editor.md` that names the document-model contract, the namespaces and the part split. Every other WFED task writes only into the folders defined here.

## 2. Context

The workflow editor is written in two parts. PART 1 (`OVE_WFED001`..`OVE_WFED049`, this task) is the editor core and the canvas behaviour. PART 2 (`OVE_WFED050`..`OVE_WFED099`, another author) is the page route and feature manifest, the workflow header, the Agent Inspector, the Chief supervision strip, the run overlay, validation display and the publish flow. PART 2 consumes the capabilities `lib:editor-document-model`, `lib:editor-commands`, `lib:workflow-mappers` and `lib:editor-session` from PART 1. The editor only creates and shows a Workflow (ADR 0002, ADR 0019): the document model is a plain-data, React-free structure that is separate from React Flow. React Flow lives only behind `ui:FlowCanvas` in `packages/ui-kit` (DS095). CONVENTIONS section 5 forbids hand-editing shared files, so this task fixes the folders and the i18n namespaces that parallel agents will use.

## 3. Scope (in)

- Folder layout with empty `index.ts` placeholders only where a folder needs a public entry (barrels are generated by the extension generators, ARCH009, so do not hand-write barrels).
- `layering.test.ts`: a Vitest test that scans the import graph of the feature and fails on forbidden imports.
- `docs/frontend/workflow-editor.md`: layering, document-model contract summary, i18n namespace table, shortcut table owner, glossary of editor terms.
- `README.md` in the feature folder (10 lines, points to the doc).

## 4. Out of scope

- Any logic (all later tasks).
- The route, `feature.manifest.ts` and page layout: PART 2 (they own `routes/` and `feature.manifest.ts`; PART 1 never creates them).
- The i18n JSON files (each task owns its own file, see requirement 3).

## 5. Detailed requirements

1. Layout (all paths under `apps/desktop/src/features/workflow-editor/`): `document/` (pure model, WFED002..WFED004), `catalog/` (WFED005), `rules/` (WFED006), `commands/` (WFED007, WFED009..WFED012), `history/` (WFED008), `mappers/` (WFED013..WFED017), `gateway/` (WFED018), `session/` (WFED019..WFED022), `agents/` (WFED023), `canvas/` (WFED024..WFED029, WFED032..WFED039), `palette/` (WFED030, WFED031), `skills/` (WFED040..WFED043), `side-rail/` (WFED044), `testing/` (builders and fixtures), `routes/` and `feature.manifest.ts` (PART 2).
2. Layering (MUST be enforced by `layering.test.ts`, which parses `import` and `export ... from` statements with the TypeScript compiler API, no regex-only scan): (a) `document/`, `catalog/`, `rules/`, `commands/`, `history/`, `mappers/` import NO `react`, NO `@xyflow/react`, NO `@overmind/api-client`, NO `@overmind/ui-kit` runtime values (type-only imports of `CanvasModel` types from `@overmind/ui-kit` are allowed ONLY inside `mappers/`); (b) `gateway/` is the only folder that imports `@overmind/api-client`; every adapter file in it is owned by the task that needs it (`gateway/workflows.ts` WFED018, `gateway/agents.ts` WFED023, `gateway/skills.ts` WFED040, `gateway/agent-skills.ts` WFED043); (c) `session/` imports `react` only in `session/react/` (hooks), the store itself is framework-free; (d) nothing outside the feature imports from `features/workflow-editor/**` except through the exports listed in the manifest of PART 2 and the capability barrels; (e) no file imports `@overmind/domain`, `@overmind/application`, `@overmind/gateway` or `@overmind/workflow-runtime` (CONVENTIONS 6).
3. i18n namespaces: PART 1 uses one namespace per slice, named `wfc-<slice>`, with the files `apps/desktop/src/locales/en/wfc-<slice>.json` and `.../pl/wfc-<slice>.json`. The task that lists the file in its `owns` is its only editor; no two tasks edit one JSON file (CONVENTIONS 5). Slices: `core` (WFED007: command labels, command errors, announcements), `load` (WFED020), `save` (WFED021), `conflict` (WFED022), `canvas` (WFED024), `view` (WFED027), `legend` (WFED029), `palette` (WFED030), `add` (WFED031), `conn` (WFED032), `del` (WFED033), `clip` (WFED034), `group` (WFED035), `lane` (WFED036), `ctx` (WFED037), `keys` (WFED038), `search` (WFED039), `skills` (WFED040), `skillrules` (WFED041), `skilldrop` (WFED042), `skillassign` (WFED043), `rail` (WFED044), `a11y` (WFED046). PART 2 uses the single namespace `workflow-editor`. The doc keeps this table; a task that needs a new slice adds a row through a proposal.
4. The document `docs/frontend/workflow-editor.md` MUST contain: the layer diagram (Mermaid), the table of capabilities with their owner task, the document-model contract invariants (copied from WFED002 once merged; until then a link), the namespace table, the rule "the editor never evaluates expressions and never runs a Workflow", and the glossary: Document, Command, Outcome, Selection, Draft, Version, Canvas model.
5. Names: code and docs English (ADR 0017); UI copy through i18n only; Polish glossary terms map as in CONVENTIONS section 10 (`Tor` is `Lane` in code, `TOR` in the UI).

## 8. Architecture and code placement

Layer: UI feature (apps/desktop). Pure core (`document`, `catalog`, `rules`, `commands`, `history`, `mappers`) <- stateful session (`session`) <- React wiring (`canvas`, `palette`, `skills`, `side-rail`). Dependencies point only that way (DIP, Clean Architecture). The test is the executable form of this rule.

## 9. Security and safety

No trust boundary of its own. The layering test is a safety control: it keeps network access in one folder (`gateway/`) and keeps the pure core free of I/O, so the model can be fuzzed and trusted to be deterministic.

## 10. Errors and edge cases

- A new folder appears that is not in the table: the test fails with the folder name and asks for a doc update.
- A type-only import of ui-kit inside `commands/`: fails (only `mappers/` may).
- Dynamic `import()` of a forbidden module: counted as an import.

## 11. Acceptance criteria

- [ ] Given the layout, When `pnpm --filter @overmind/desktop test layering` runs, Then it passes on the empty skeleton.
- [ ] Given a probe file in `document/` importing `react`, When the test runs, Then it fails naming the file and the rule.
- [ ] The doc lists every WFED001..WFED049 capability with its owner.

## 12. Test plan

`layering.test.ts` with an in-memory file set fixture (a small virtual project) for positive and negative cases, plus the real scan. Command: `pnpm --filter @overmind/desktop vitest run src/features/workflow-editor/layering.test.ts`.
