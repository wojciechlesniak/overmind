# Thin native shell integration

The Owner authorizes sequential implementation, necessary integration, reviews and
passing merges to DEVELOP. SETUP010 keeps all engine/business policy outside Rust.
The pinned Tauri2.12.3 features were verified against crates.io on2026-10-16 and
match tray-icon/wry/compression with defaults disabled. Rust1.90.0 is installed and
verified in a private project toolchain cache; the user's default remains unchanged.

The byte bridge uses exact, mature MIT dependencies: hyper1.12.0 (HTTP/1 client),
hyper-util0.1.21 (Tokio IO adapter), http-body-util0.1.5 (bounded body collection),
and nix0.31.3 (safe UID/peer checks without unsafe application code). These replace
a handwritten HTTP framing/parser and unsafe libc calls. Direct register blocks
will record value, maintenance, alternatives and risks before acceptance. Tokio
explicitly enables time/sync for required timeouts and cancellation; its test-only
macro/runtime features are separate. No network client transport is added: Hyper
receives only the owner-checked Unix socket, never a TCP connector or URL resolver.

Node/package CI integration, capability/config guard protection, and the hosted
macOS Rust job will be updated through the existing foundation gates. No physical
escape test is run on the user's daily-use Mac, and the accepted SETUP006 release
isolation deferrals remain mandatory. License policy, registry sources, age rules
and exceptions are unchanged; a failed license check blocks merge.

Two small, explicitly owned native modules deepen the transport seam: native_io.rs
holds owner-checked sockets/private logging and shared layout; transport.rs holds
validated HTTP bytes. The original modules remain thin Tauri/lifecycle adapters.
The source allow-list and per-file200line guard include both additions. This changes
placement only, not permissions or business scope. The permission TOML files are
autogenerated by the pinned AppManifest::commands implementation and committed.

Tauri's pinned build helper copies declared sidecars even during cargo check. A
debug-only generated build config in OUT_DIR omits an absent sidecar for that copy
step, while the canonical runtime/release config keeps its exact declaration.
Release builds never omit it; no fake engine binary is created. Main window creation
is deferred until setup attaches navigation/new-window denials. The actual SWC dev
HTML includes an inline Fast Refresh preamble, so only devCsp permits inline scripts.

The subscribe transport accepts optional forwarded headers, using the same shape
validation as requests. The original signature omitted headers although gateway
authentication requires the client to attach its bearer header. Optional forwarding
closes that inconsistency without adding token storage or authentication logic.

A separate `sidecar.rs` owns process event collection and a cancellation-safe child
handle. It keeps `engine.rs` below the required 200 lines and ensures that dropping
the outer timeout cannot leave a hung helper running. All eight Rust source files
are listed explicitly by the configuration guard.

The Rust CI job uses the standard hosted `macos-26` arm64 runner, matching the
minimum supported OS; the foundation workflow test now asserts that exact label
instead of requiring the old optional `MACOS_RUNNER` variable. This job performs
compilation and socket/ACL tests only, not physical isolation escape tests.
Source: https://docs.github.com/en/actions/reference/runners/github-hosted-runners

Review corrections: exacl 0.13.0 (MIT, Rust 1.85, published 2026-05-05) reads real
macOS extended ACLs through a safe API. Private directories, sockets and log files
reject any ACL and unreadable ACL metadata, including inherited grants; chmod +a
regressions preserve the 0700/0600 modes. Tauri's actual `is_dev()` mode controls the
Vite navigation exception, so a bundled custom-protocol debug build rejects it.
